## 二、零基础原理详解（可作论文 Method 章节底稿）

### 1. 为什么联邦入侵检测需要 StatAvg？
在物联网（IoT）与企业网络入侵检测（IDS）中，各参与方（如不同医院、工厂或网关）持有本地流量或主机内存审计日志，因隐私合规无法共享原始数据，因此采用联邦学习（Federated Learning, FL）协同训练检测模型。

然而，神经网络对输入特征尺度高度敏感，训练前必须执行标准化（Z-score Normalization）：
$$\tilde{x} = \frac{x - \mu}{\sigma}$$
在传统 **FedAvg** 中，各客户端仅用自身本地数据的 $(\mu_k, \sigma_k)$ 归一化。由于不同站点的流量基线和攻击分布高度异质（Feature Skew / Non-IID），同一原始观测在不同客户端会被映射到完全不同的标准化数值，导致局部梯度冲突、全局模型收敛缓慢且精度偏低。

**StatAvg（Bouzinis 等，IEEE TNSM 2025 / arXiv:2405.13062）** 在训练启动前（Round 1）增加一次轻量统计量交换：每个客户端 $k \in \{1,\dots,K\}$ 上报本地样本数 $n_k$、特征均值向量 $\mu_k \in \mathbb{R}^D$ 与方差向量 $\sigma_k^2 \in \mathbb{R}^D$。服务器按精确合并公式计算全局统计量：
$$\mu_g = \frac{\sum_{k=1}^{K} n_k \mu_k}{\sum_{k=1}^{K} n_k}, \qquad \sigma_g^2 = \frac{\sum_{k=1}^{K} n_k \left[\sigma_k^2 + (\mu_k - \mu_g)^2\right]}{\sum_{k=1}^{K} n_k}$$
随后服务器将 $(\mu_g, \sigma_g)$ 广播给全体客户端，所有客户端统一使用该全局归一化器预处理数据，再执行标准 FedAvg 联邦训练。

### 2. 核心漏洞：为什么 StatAvg 的统计量聚合极其脆弱？
仔细观察上面的官方公式可以发现三个致命隐患：
1. **无边界敏感性（Unbounded Breakdown Point = 0）**：均值与合并方差均为线性/二次加权和，只要**单个恶意客户端**发送极端伪造的 $\tilde{\mu}_k$ 或 $\tilde{\sigma}_k^2$，就可以将全局 $(\mu_g, \sigma_g^2)$ 拉偏至任意值；更致命的是，$\sigma_g^2$ 中的 $(\mu_k - \mu_g)^2$ 项会**二次放大**均值偏移对全局方差的污染！
2. **权重可伪造（Sample-Count Inflation）**：权重 $n_k$ 由客户端自报，服务器看不到原始数据无法核验。恶意客户端谎报 $\tilde{n}_k = \gamma n_k$（如 $\gamma = 5$）即可凭空占据数倍聚合话语权。
3. **绕过全部模型层防御（Bypassing Model-Level Byzantine Defenses）**：投毒**仅发生在第 1 轮统计量交换**；从第 2 轮到最后一轮，恶意客户端完全诚实地执行本地训练并上传正常梯度/权重。因此，所有监控训练阶段梯度或模型权重的经典拜占庭防御（如 Multi-Krum、Bulyan、坐标中位数权重聚合）根本无法发现异常！

### 3. 五种统计量投毒攻击定义（`statavg_poison/poison.py`）

| 攻击名称 | 数学操作 | 物理/训练破坏机制 |
|---|---|---|
| `mean_shift`（均值平移） | $\tilde{\mu}_k = \mu_k + \alpha \sigma_k$ | 整体偏移所有诚实客户端的输入分布，同时经由 $(\mu_k - \mu_g)^2$ 项剧烈拉大全局方差 |
| `var_inflate`（方差放大） | $\tilde{\sigma}_k^2 = \beta^2 \sigma_k^2$ | 全局标准差暴增，诚实客户端的所有特征被压扁到 0 附近，不同攻击类别丧失可分性 |
| `var_shrink`（方差缩小） | $\tilde{\sigma}_k^2 = \sigma_k^2 / \beta^2$ | 叠加样本数谎报后显著压低局部方差贡献，引起特征尺度畸变与梯度震荡 |
| `hijack`（复合劫持，最强） | 同时执行 $\tilde{\mu}_k = \mu_k + \alpha \sigma_k$ 与 $\tilde{\sigma}_k^2 = \sigma_k^2 / \beta^2$ | 同步破坏中心位置与离散度，在叠加 `n_inflate` 后使 Vanilla StatAvg 全面崩塌 |
| `targeted_shift`（定向隐蔽投毒） | 仅对前 25% 高方差关键特征施加偏移与方差放大 | 保持其余 75% 特征完全正常，专门检验全向量检测 vs 逐特征分位检测的灵敏度 |

> 以上攻击均可叠加 **样本数谎报（`n_inflate`）**：$\tilde{n}_k = \gamma n_k$（默认 $\gamma = 5$）。

### 4. 五种统计量聚合防御机制（`statavg_poison/robust_stats.py`）

| 防御名称 | 算法核心 | 特点与适用场景 |
|---|---|---|
| `vanilla`（无防御基线） | 官方样本数加权均值 + 合并方差 | 崩溃点为 0，极易被攻破 |
| `n_clip`（样本数截断） | $\hat{n}_k = \min(n_k, 2 \cdot \text{median}(n))$ 后按官方公式聚合 | 仅消融测试用：可抑制权重放大，但无法挡住极端统计量数值 |
| `median`（坐标中位数） | 逐特征取中位数均值，方差取组内中位数加组间偏差中位数 | 抗 50% 以下异常值，但在异质数据下有轻微估计偏差 |
| `trimmed`（截尾均值） | 逐特征去掉最高与最低各 20% 极值后再加权合并 | 平滑稳健，适合已知恶意比例上限不超过截尾比例的场景 |
| **`mad_filter`（推荐方法）** | 对每个客户端的均值 $\mu_k$ 与对数方差 $\log(\sigma_k^2 + \epsilon)$ 分别计算逐特征修正 Z-score（基于中位数与 MAD），取特征维 85% 分位数作为客户端异常分；剔除超过阈值（3.5）的离群客户端（保底保留 $\ge 50\%$），对保留客户端施加 `n_clip` 后按**精确 StatAvg 公式**合并 | **三重优势**：① 干净场景下几乎零误杀、零精度损失；② 攻击场景下既能精准恢复全局统计量，又能输出被剔除的恶意客户端名单（供审稿人看检测 Precision/Recall/F1）；③ 对定向隐蔽攻击同样敏感 |

## 三、实验环境、数据集与官方对齐参数

### 1. 与官方 Flower StatAvg 基线 100% 对齐的配置
- **模型架构**（复现 `flwrlabs/flower/baselines/statavg/statavg/model.py`）：
  3 层隐藏全连接网络（MLP）：`Input(D) -> Linear(128) -> ReLU -> Linear(128) -> ReLU -> Linear(128) -> ReLU -> Linear(C)`
- **优化器与超参**：`Adam(lr=0.002, betas=(0.99, 0.999), eps=1e-8)`，`batch_size=512`，`local_epochs=2`，`num_rounds=40`
- **主数据集**：**TON_IoT Linux Memory**（`Train_test_linux_memory.csv` $\rightarrow$ 放至 `dataset/dataset.csv`）

- **第二数据集（可选泛化实验）**：TON_IoT Network CSV 或 CICIoT2023 抽样子集（代码 `dataset.py` 已原生兼容任意表格型 IDS CSV）。
- **联邦非独立同分布划分**：10 个客户端，Dirichlet($\alpha=0.5$) 非独立同分布划分，全局分层留出 20% 作为测试集。
